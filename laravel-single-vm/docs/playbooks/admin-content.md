# Manage public content in an admin area

Use when an administrator needs to create, edit or delete content shown on public pages. Paths below start in `apps/web`.

1. Inspect the User model, existing gates and requested public page. Follow `docs/playbooks/fortify-auth.md` for an admin flag defaulting to false and a gate such as `manage-content`. Reuse an existing admin privilege where appropriate. Keep the flag out of registration and profile inputs. An editor-only permission for another page does not confer admin rights.
2. Give the owner a first-run page at `/admin/setup`. Map `ADMIN_SETUP_TOKEN` with `env()` in a Laravel config file and read it server-side through `config()`. The owner generates a random 32-byte hex token and saves it in Studio under **Application settings → Variables and secrets → Add entry**, type **Secret**. Wait for the preview to apply the saved settings. Publishing the Single VM with that environment revision supplies the value to the app via the release's private `.env.production`. A change to the live site's environment takes a new publish. Keep the value out of Git, prompts, URLs, logs and Inertia props.
3. Keep setup GET and POST in the web middleware group, outside both registration and the admin gate. Return 404 on both when the configured token is empty, setup has been claimed, or an admin already exists. Accept the token, name, email, password and confirmation through a CSRF-protected form. Compare with `hash_equals` on the server; reject a wrong token without creating anything. Never flash the submitted token or passwords back. In one database transaction claim a unique, durable setup record, call Fortify's `App\Actions\Fortify\CreateNewUser` with the account fields, then set the admin flag server-side. Roll back on failure; refuse a concurrent or later claim. Redirect to sign-in. The claim survives restarts and account deletion. Never promote the first public registrant.
4. Create a migration per affected table in `database/migrations`. For news, add a news items table with the requested fields (for example title and body), a primary key and timestamps. Add the Eloquent model in `app/Models`. Preserve existing rows and migrations. Apply with `project_check` migrations.
5. In `routes/web.php`, group the admin routes under the admin URL and route-name prefixes with `['auth', 'can:manage-content']`. Register a resource controller restricted to index, create, store, edit, update and destroy. Use route model binding, Form Requests for create/update, explicit validated fields and redirect after successful writes. Keep the public read outside this group. Replace the static public route with a controller that queries the saved items in a deterministic order and passes the public fields to the existing Inertia page.
6. Under `resources/js/pages/admin`, build list, create and edit pages. Use a confirmed delete action on the list or edit page. Read the starter's shadcn-ui playbook; use the installed Button, Input, Label, Card and Dialog components and a native textarea for long text. Use Inertia Link for navigation and Form bound to Wayfinder actions for store, update and destroy. Show field errors and disable duplicate submissions while processing. Render stored content as escaped Vue text on the public page. Show admin navigation only to authorized users; enforce the gate on every admin request.
7. In `tests/Feature`, test setup GET and POST with no configured token, refusal of a wrong token, successful setup with the right token, and refusal of the same token on a second attempt. Assert the account count and admin flag after each submission. Exercise every guarded admin route as a guest, ordinary user and admin. Check redirects to login, forbidden responses and unchanged data after denied mutations. As admin, assert list/create/edit page responses, create/update validation errors, successful writes and deletion in the database. Request the public page after each change and assert its Inertia props reflect it. Run `project_check` verify. In the preview create a news item through the admin form, reload the public page, edit it, then confirm deletion and check the public page again.
