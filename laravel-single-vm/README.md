# Laravel single-VM starter

Laravel 13 (PHP 8.5) on the official [Laravel Vue starter kit](https://github.com/laravel/vue-starter-kit) (commit `1959e1a26b1c`): Inertia 3, Vue 3, TypeScript, Tailwind 4, shadcn-vue, Wayfinder and Fortify, built with Vite+. PostgreSQL 18 is the database. The application is in `apps/web`; the kit's pages (welcome, register, login, dashboard, settings) are the starting point.

Install PHP 8.5 (with `pdo_pgsql`, `intl`, `bcmath`, `zip`), Composer 2.11, Node 24, Bun 1.4.5 and PostgreSQL 18. In `apps/web`, copy `.env.example` to `.env`, set `DB_URL`, then run `composer install`, `php artisan key:generate`, `php artisan migrate`, `bun install --frozen-lockfile` (from the repository root) and `bun run build --watch`, and serve it with `php artisan serve`. Open http://127.0.0.1:8000. The build generates the Wayfinder route helpers with `php artisan`, so it needs the PHP dependencies installed first.

`bun run lint`, `bun run build`, `bun run typecheck` and `bun run test` run Pint and `vp check` (oxlint, oxfmt), the production build, `vue-tsc` and Larastan (level 7), and PHPUnit. Build before the type check and the tests: the build generates the Wayfinder route helpers that `vue-tsc` imports and the manifest the tests render through. The tests need PHP's `pdo_sqlite`.

On a VM, write the application's environment values to `.env.production` beside `compose.yaml`, one `NAME='value'` line each (a value cannot contain `'`). Export `VBSMO_HOSTNAME`, an absolute `VBSMO_DATA_DIR` on the mounted data disk, and `VBSMO_DB_PASSWORD` (a random hexadecimal password, for example `openssl rand -hex 32`) in the shell that runs `docker compose`, not in `.env.production`. `docker compose up -d --build` builds the app from `Dockerfile` (FrankenPHP in classic mode behind Caddy) and starts it with PostgreSQL 18 and Caddy, which obtains the certificate for the hostname. The container runs the migrations and `php artisan optimize` at start and creates `APP_KEY` once in `app/app-key` on the data disk. Keep `app/`, `postgres/` and `caddy/` under `VBSMO_DATA_DIR` across releases: `storage/` lives in `app/storage` and uploads in `app/uploads`.

## Changes from laravel/vue-starter-kit

Everything not listed here is the kit's own file. Each change is the smallest edit that its reason needs.

- **Pinned versions.** Every dependency in `apps/web/package.json` and `apps/web/composer.json` is the exact version the committed `bun.lock` and `composer.lock` resolve, instead of the kit's `^` ranges, so that a build is repeatable and works offline from the builder's cache. `@inertiajs/core` is a direct dependency: the kit's `pnpm-workspace.yaml` hoists it for pnpm, which Bun does not read, and the kit's pages import its types. `laravel/chisel` is removed after it ran: its `install:features` command only chooses the kit's features once.
- **PostgreSQL.** `.env.example` and `config/database.php` default to `pgsql`; the connection reads the preview platform's description file or `DB_URL`. The tests still use the kit's in-memory SQLite.
- **Behind a proxy.** `bootstrap/app.php` trusts all proxies, and `config/session.php` defaults to `SameSite=None; Secure` cookies: the preview is shown in a cross-site frame, and the preview gateway and the production Caddy terminate TLS.
- **Data disk.** `config/filesystems.php` puts the `local` and `public` disks and the `storage:link` target under `UPLOADS_DIR`, the kept uploads directory.
- **No background work.** `QUEUE_CONNECTION=sync`, `CACHE_STORE=file`, the log goes to stderr; there is no scheduler, queue worker or websocket server.
- **Production files.** `Dockerfile` builds the assets in a PHP stage, because the Wayfinder generator runs `php artisan`; `Dockerfile.dev`, `Caddyfile`, `Caddyfile.app`, `compose.yaml` and `.vbsmo.json` describe the single-VM deployment and the platform contract.
- **Scripts.** `apps/web/package.json` adds `lint`, `lint:fix`, `typecheck` and `test`, which the platform and the root workspace call, on top of the kit's `build`, `dev` and `check`.
- **Repository linter.** The root Biome (`biome.json`) does not lint `apps/web/resources/js`: the kit lints and formats its Vue and TypeScript with `vp check`, and Biome's Vue rules reject the kit's own code.
- **Email verification removed.** The starter has no mail transport, so a user who registers could never verify the address and reach the dashboard. The kit's `email-verification` switch (`install:features`) removed `MustVerifyEmail`, the verification page and its routes.
- **Passkeys removed.** Passkeys (WebAuthn) cannot work in the preview: the Studio frame grants no `publickey-credentials-*` permission to the cross-site preview, and the relying party and allowed origins come from `APP_URL`, which differs from the preview's address; registering one failed in the frame (`/user/passkeys/options` answered 503). The kit's `passkeys` switch (`install:features`) removed the package `@laravel/passkeys`, the passkey components, the migration and the passkey routes and tests. Two-factor authentication, password confirmation and the appearance switch were proven in the frame and are kept.
- **Agent files.** `AGENTS.md` and `docs/playbooks/shadcn-ui.md` describe this layout for the coding agent.
