# Laravel single-VM application

This Bun workspace holds one Laravel 13 application (PHP 8.5) in `apps/web`: the official Laravel Vue starter kit with Inertia 3, Vue 3, TypeScript, Tailwind 4 and shadcn-vue, built with Vite+ (`vp`). PostgreSQL 18 is the only database. Your training data describes older Laravel and Inertia versions; follow these rules.

Laravel 13 structure:
- There is no `app/Http/Kernel.php`. Middleware, routing and exceptions are configured in `bootstrap/app.php`; providers are listed in `bootstrap/providers.php`. Do not remove `trustProxies(at: '*')`: the preview and production sit behind a proxy.
- Create files with `php artisan make:model|migration|controller|request|test ... --no-interaction`. Add a new migration for every schema change; never edit or delete one that exists. Migrations are written by hand: there is nothing to generate.
- Use Eloquent models and Form Requests (`make:request`) and named routes. Read configuration only through `config()`; call `env()` only inside `config/`.
- Sign-in is Laravel Fortify (`config/fortify.php`, `app/Providers/FortifyServiceProvider.php`), already wired to the kit's pages: `/login`, `/register`, `/logout`, `/dashboard` and `/settings/*` work. Do not install another starter kit, Breeze, Jetstream, Sanctum or Socialite, and do not write your own login.

Read `docs/playbooks/fortify-auth.md` for sign-in features or restricted pages, `docs/playbooks/laravel-i18n.md` for a multilingual site, and `docs/playbooks/admin-content.md` for an admin area that manages public content.

Inertia 3 with Vue:
- A controller returns `Inertia::render('Page', [...])` (or a route uses `Route::inertia('path', 'Page')`); pages are Vue single-file components (`<script setup lang="ts">`) in `resources/js/pages` (`Dashboard.vue` renders `Dashboard`, `settings/Profile.vue` renders `settings/Profile`). Shared props are set in `app/Http/Middleware/HandleInertiaRequests.php`; the layout of a page is chosen in `resources/js/app.ts`.
- Link and submit through Inertia: `<Link>`, `<Form>` and `useForm` from `@inertiajs/vue3`, which send the CSRF token and show validation errors. Never write `fetch` or `axios` calls for forms and do not add a separate JSON API.
- Routes and form actions come from Wayfinder: import the generated controller or route functions from `@/actions/...` and `@/routes/...` (for example `<Form v-bind="store.form()">`) instead of writing URL strings. They are generated by the build from the PHP routes and are not committed; build after changing a route.
- There is no hot reload: the preview rebuilds the frontend on every save; reload the page.

Platform:
- The platform provides the preview PostgreSQL (`config/database.php` reads it). Never run `initdb`, start a PostgreSQL, switch to SQLite (only tests use SQLite) or seed or reset an existing database. Apply migrations with the `project_check` tool.
- Do not start `php artisan serve` or any dev server: the platform previews the app. Do not run `composer update`, `npm` or `npx`.
- Sessions use `SameSite=None; Secure` cookies because the preview is framed; do not change them and do not disable CSRF protection.
- Keep the root `bun.lock` and `apps/web/composer.lock` synchronized with the dependencies, and pin exact versions.

Quality (run after the requested feature works, and fix everything they report): `project_check` with `verify` runs Pint and `vp check` (oxlint and oxfmt; `vp check --fix` formats), the build, `vue-tsc` and Larastan (level 7, `phpstan.neon`), then PHPUnit (`vendor/bin/phpunit`, not `php artisan test`, which warns when `.env` is missing; the tests render pages through the build). Add a feature test in `tests/Feature` for every route you add. The checks must print nothing.

UI uses the installed shadcn-vue components in `apps/web/resources/js/components/ui` (reka-ui) and the icons of `@lucide/vue`; read `docs/playbooks/shadcn-ui.md` before adding components. Build pages and sections from these components, and from the kit's layouts in `resources/js/layouts`. Colours live in `apps/web/resources/css/app.css` as neutral placeholders; replace them with the site's palette. Fonts: the page uses the system sans-serif stack; a chosen font comes from font files committed in the project through `local()` from `laravel-vite-plugin/fonts` in `vite.config.ts` (the build has no network, so no remote font provider). Dark mode is the kit's appearance switch (`useAppearance`, `/settings/appearance`).

## File map

Edit: `apps/web/routes/web.php`, `apps/web/app/Http/Controllers`, `app/Models`, `app/Http/Requests`, `database/migrations`, `resources/js/pages` (one file per page), `resources/js/components` and `resources/js/layouts` (the sidebar navigation is `components/AppSidebar.vue`, the public page is `pages/Welcome.vue`), `resources/css/app.css`, `tests/Feature`.
Plumbing, no reading needed for ordinary work: `bootstrap/`, `config/`, `vite.config.ts`, `tsconfig.json`, `phpstan.neon`, `pint.json`, `composer.*`, `package.json` files, `Dockerfile*`, `Caddyfile*`, `compose.yaml`, `.vbsmo.json`, `bun.lock`. `resources/js/actions`, `routes` and `wayfinder` are generated: never edit them.

## Site shape and starter leftovers

Build only what the request asks for, with the smallest set of files: do not add queues, jobs, a scheduler, events, notifications, mail, policies, API resources, repositories or service layers, and do not add features nobody requested. A site is a multi-page application: its sections are separate routes and pages (the pages follow from the request).
The kit's pages are the starting point: `Welcome.vue` is the public page, `Dashboard.vue` is the signed-in page with the sidebar, and settings holds the profile, password and appearance. The kit's placeholder texts, the "Laravel" name and the demo links in the sidebar and in `Welcome.vue` are placeholders: replace them and choose the visual design from the request. A site with no stored data needs no table, controller logic or migration. Do not look for or copy files of other starters (`packages/db`, drizzle, `src/routes`, TanStack, Next.js, React): they do not exist here.
