# Serve a site in more than one language

Use when visitors need translated pages and a language switch. Application paths are relative to `apps/web`. Playbook paths (`docs/playbooks/`) are relative to the project root.

1. Keep supported locales in one list in `config/app.php` and retain English as the default and fallback. The starter has no `lang/` directory. Run `php artisan lang:publish` from `apps/web` to create the English framework files. Add Russian counterparts for `auth.php`, `passwords.php` and `validation.php` under `lang/ru`, and add matching application keys to `lang/en/site.php` and `lang/ru/site.php`. Group strings by page or shared control. Translate the visible labels, navigation, page titles and form messages within the requested scope. Fortify's Vue pages keep their English labels unless the request includes them; move those strings to the site translation files when requested. Use Laravel's translator without adding a client translation package.
2. Add a named POST route in `routes/web.php` that validates the submitted locale against the configured list, saves it to the session and redirects back. Add web middleware in `app/Http/Middleware` that calls `App::setLocale()` on each request using the supported session locale or the configured default. In the existing `$middleware->web(append: [...])` call in `bootstrap/app.php`, insert the locale middleware between `HandleAppearance::class` and `HandleInertiaRequests::class`. The session is available there. Keep the web session and CSRF middleware intact.
3. In `app/Http/Middleware/HandleInertiaRequests.php`, share the active locale, language choices and the needed translated labels alongside the existing props. Use Laravel translation keys, e.g. `__('site.navigation')`. Type the shared values in `resources/js/types/global.d.ts`. Read them reactively from `usePage().props` in Vue. Render the language switch on the requested layouts/pages with an Inertia Form bound to the generated Wayfinder route; submit the selected locale. Keep the document's lang attribute in sync on both initial render and Inertia navigation.
4. Add validation translations for rules used by the forms in `lang/ru/validation.php`, retaining placeholders such as `:attribute` and providing translated attribute labels. The middleware selects the locale before Form Request validation. Display the returned field errors beside inputs.
5. In `tests/Feature`, check the default English labels, the switch redirect, Russian labels on the next request and after navigation, a Russian validation error, and switching back. Reject unsupported locales and retain the previous choice. Run `project_check` verify. Switch languages in the preview, follow a link, reload and submit an invalid form to check both the session and rendered translations.
