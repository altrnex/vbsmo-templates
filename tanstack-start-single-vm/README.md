# TanStack Start single-VM starter

Install Bun 1.4.4 and PostgreSQL 18. Set `DATABASE_URL` for your local database, then run `bun install --frozen-lockfile`, `bun run db:migrate`, and `bun run dev`. Open http://127.0.0.1:3000. The notes API persists data in PostgreSQL.

Run `bun run db:check` to check that the database migration history matches the source without changing data. Run `bun run build` for the production build (`apps/web/.output`). Production needs `DATABASE_URL` and the committed migrations; the image runs those migrations before starting. Database data belongs on a persistent disk outside the image. Run `bun run db:generate` after changing `packages/db/schema.ts` and commit the generated migration.

On a VM, write the application's environment values to `.env.production` beside `compose.yaml`, one `NAME='value'` line each (a value cannot contain `'`); the build and the app read them from that file. Export `VBSMO_HOSTNAME`, an absolute `VBSMO_DATA_DIR` on the mounted data disk, and `VBSMO_DB_PASSWORD` (a random hexadecimal password, for example `openssl rand -hex 32`) in the shell that runs `docker compose`, not in `.env.production`. `docker compose up -d --build` builds the app from `Dockerfile` and starts it with PostgreSQL 18 and Caddy, which obtains the certificate for the hostname. Keep `app/`, `postgres/` and `caddy/` under `VBSMO_DATA_DIR` across releases. `UPLOADS_DIR` points to persistent app uploads (`/data/uploads` in Compose); preview checkpoints capture its media directory alongside PostgreSQL. Read `docs/playbooks` when adding optional integrations.
