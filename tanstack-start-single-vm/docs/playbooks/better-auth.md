# Better Auth in a TanStack Start single-VM application

Use when the application needs sign-in, sessions, or protected routes. Applies to `tanstack-start-single-vm`; the Hono router and Drizzle PostgreSQL database are already present.

1. Inspect `apps/web/src/server/api.ts`, `db.ts`, `packages/db/schema.ts`, `src/routes/api/$.ts` and existing auth code. Preserve a working auth installation. Decide sign-in methods, registration policy, public origin and email delivery with the user where the request does not establish them.
2. Add pinned `better-auth` to `apps/web` with Bun. Create `apps/web/src/server/auth.ts` with one `betterAuth({ database: drizzleAdapter(db, { provider: "pg" }), ... })` instance over the existing Drizzle database (`drizzleAdapter` from `better-auth/adapters/drizzle`; `getDb()` is async, so export `getAuth()` as an async function that awaits `getDb()` once and caches the instance; every use is `(await getAuth())`), and `plugins: [tanstackStartCookies()]` from `better-auth/tanstack-start` as the LAST plugin. Generate the auth schema with the Better Auth CLI, add it to `packages/db/schema.ts`, generate and inspect a checked-in migration (`bun run db:generate`), then apply it (`bun run db:migrate`).
3. Mount the handler as its own server route `apps/web/src/routes/api/auth/$.ts`: `createFileRoute("/api/auth/$")({ server: { handlers: { GET, POST } } })`, each calling `(await (await import("../../../server/auth.ts")).getAuth()).handler(request)`. This route is more specific than `api/$.ts`, so it wins; do not mount auth inside the Hono router. Configure a stable `BETTER_AUTH_SECRET`, `baseURL`, `trustedOrigins`, and secure host-scoped cookies. Keep secrets out of Git, client bundles and image layers.
4. Read the session in server functions and routes: `(await getAuth()).api.getSession({ headers: getRequestHeaders() })` (`getRequestHeaders` from `@tanstack/react-start/server`). Guard protected routes in `beforeLoad` with a server function that returns the session and `throw redirect({ to: "/login" })` when absent. Hono actions get the request headers directly. Server functions already carry the CSRF check from `src/start.ts`; keep it.
5. Use the client from `better-auth/react` (`createAuthClient`) for sign-up, sign-in and sign-out in the browser.
6. Verify sign-up/sign-in as requested, protected access, sign-out, invalid-session behaviour and session continuity after restart. Verify a fresh installation and a database that already contains notes. Do not overwrite either database.

Primary references: [Better Auth TanStack Start](https://better-auth.com/docs/integrations/tanstack), [Drizzle adapter](https://better-auth.com/docs/adapters/drizzle).
