# Internationalisation with Paraglide (TanStack Start)

Use when the site needs more than one language. Applies to `tanstack-start-single-vm`. This follows TanStack's official `start-i18n-paraglide` example; check it against the installed versions.

1. Add the current `@inlang/paraglide-js` (3.x; steps 2-4 were checked with 3.2.2), pinned exactly, to `apps/web`. Create `apps/web/project.inlang/settings.json` (`baseLocale`, `locales`, `modules` for the message format plugin, and `"plugin.inlang.messageFormat": { "pathPattern": "./messages/{locale}.json" }`: without it no message is compiled) and message files `apps/web/messages/<locale>.json` (flat `"key": "text"` entries).
2. In `apps/web/vite.config.ts` add `paraglideVitePlugin({ project: "./project.inlang", outdir: "./src/paraglide", outputStructure: "message-modules", strategy: ["url", "cookie", "preferredLanguage", "baseLocale"], urlPatterns: [...] })` before `tanstackStart()`. `urlPatterns` map `/` and `/:path(.*)?` to `/<locale>` and `/<locale>/:path(.*)?` per locale. The compiled `src/paraglide` folder is generated but COMMIT it: the preview and the production build restore the project from Git, and `src/server.ts` imports `./paraglide/server.js`, which must exist before the dev server loads. Never add it to `.gitignore`. Add `src/paraglide` to the exclusions in the repository's `biome.json` (`files.includes`, `"!**/paraglide"`) so lint skips it, and commit the regenerated folder whenever messages change (run `bun run build` once after editing messages).
3. In `src/router.tsx` add `rewrite: { input: ({ url }) => deLocalizeUrl(url), output: ({ url }) => localizeUrl(url) }` to `createRouter` (imports from `./paraglide/runtime`), so route files stay locale free.
4. Create `src/server.ts` that wraps the TanStack handler: `import handler from "@tanstack/react-start/server-entry"; import { paraglideMiddleware } from "./paraglide/server.js"; export default { fetch: (req: Request) => paraglideMiddleware(req, () => handler.fetch(req)) };`.
5. Use messages as `import { m } from "@/paraglide/messages"; m.some_key()`; set `<html lang={getLocale()}>` in the root route; switch language with `setLocale(locale)`.
6. Verify each locale URL renders its language on first load (view-source, not only after hydration), the switcher keeps the path, and `bun run build` passes. Server functions and `/api` keep working under a locale prefix.
