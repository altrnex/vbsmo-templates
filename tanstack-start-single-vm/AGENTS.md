# TanStack Start single-VM application

This Bun workspace runs one TanStack Start (React) server in `apps/web`, built with Vite. The database schema and migrations live in `packages/db` (Drizzle ORM, PostgreSQL 18). Routes are file based in `apps/web/src/routes`; `apps/web/src/routeTree.gen.ts` is generated by the dev server: never edit it.

Use ONLY the current TanStack Start 1.x API. Your training data contains older versions; these are the mistakes to avoid:

- Packages are `@tanstack/react-start` and `@tanstack/react-router`. Never import `@tanstack/start`, `@tanstack/start/server`, `@tanstack/react-start/api` or `vinxi`.
- There is no Vinxi and no `app.config.ts`. Configuration is `apps/web/vite.config.ts` with the plugins `tanstackStart()` from `@tanstack/react-start/plugin/vite`, `nitro()` from `nitro/vite` and `react()`. Scripts are `vite dev` and `vite build`; never add `vinxi` scripts.
- The router is `getRouter()` exported from `src/router.tsx`; there are no `createRouter` default exports, no `client.tsx` or `ssr.tsx` entries, and no `app/` directory.
- Server functions: `createServerFn({ method: 'POST' }).validator(schema or function).handler(async ({ data }) => ...)`. The validation method is `.validator(...)`; `.inputValidator(...)` does not exist in the installed version. Call a server function from components as `await fn({ data })`; load data in a route with `loader` or call from `useQuery`. Check the installed type definitions when unsure.
- Cookies and request data come from `@tanstack/react-start/server`: `getCookie`, `setCookie`, `getRequest`, `getRequestHeader`. There is no `useSession`, `getSession` or `getWebRequest`. For login use Better Auth (read `docs/playbooks`) or plain signed httpOnly cookies set with `setCookie`.
- Routes: `createFileRoute('/path')({ component, loader })` from `@tanstack/react-router`. Navigation: `Link`, `useNavigate`, `useRouter().invalidate()` after a mutation. The root route uses `createRootRoute` with `HeadContent`, `Scripts` and `Outlet`.
- Server-only code (database, secrets) is reached only through `createServerFn` handlers or server routes. Import `src/server/*` with `await import("../server/db.ts")` inside the handler, never at the top of a component file.
- `src/start.ts` registers the CSRF middleware for server functions. Do not remove it and do not set `allowRequestsWithoutOriginCheck`.

PostgreSQL is the only database. Use `getDb()` from `apps/web/src/server/db.ts` (Drizzle over Bun SQL). Define tables in `packages/db/schema.ts`; generate a migration with `bun run db:generate` from the repository root and apply it with `bun run db:migrate` before starting. Never seed or replace an existing database on restart. The platform provides the preview PostgreSQL (`VBSMO_PREVIEW_DATABASE_FILE`): never run `initdb` or start a PostgreSQL yourself, and run migrations through the `project_check` tool.

Keep the root lockfile synchronized when adding dependencies and pin exact versions. Verify with `bun run build` after the requested feature works. Do not start a dev server yourself: the platform previews the app.

UI uses the preinstalled shadcn/ui components; read `docs/playbooks/shadcn-ui.md` before adding UI components. Colours live in `apps/web/src/styles.css` as neutral placeholders; replace them with the site's palette and fonts. Optional integrations have playbooks in `docs/playbooks`: `better-auth.md` (sign-in), `tanstack-start-i18n.md` (several languages) and `admin-content.md` (owner-editable content). Read the one the request needs before starting. The HTTP API is the Hono router in `apps/web/src/server/api.ts`, mounted by the catch-all server route `src/routes/api/$.ts`: chain Hono methods, validate with `zValidator`, export `ApiType` and call it from the browser with the typed `hc` client; compose routers with `.route()`.
